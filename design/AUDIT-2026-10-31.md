# MICROCURE — FULL PRODUCTION AUDIT

**Date:** 2026-10-31  
**Scope:** every shipped system in the web build: title and hospital screens, case
and loadout flow, all organ generators, combat, Host Integrity, save/checkpoint,
progression, audio, accessibility, input, rendering and the audit itself.  
**Bar:** the design lock's definition of done — complete and polished for the
vertical slice, not a feature-volume promise.

  marrow, intestine, lymph and heart.
- Result: **0 generation exceptions**, 0 invalid room/node coordinates, valid
  gate counts, extract present in every non-final organ, boss present in the
  heart.
- Start-of-organ draw calls ranged **202–398** (budget: 520); the heart scene
  rendered at 202.
- Frame probe on the brain biome with 28 live enemies: **98.3 fps average**,
  **9.1 ms p95**, **125 visible draw calls**, 7 lights on the test machine.
  A 476 ms maximum sample occurred on the first manually loaded frame, where the
  probe intentionally bypassed the injection prewarm; it is not yet proof of a
  gameplay hitch under the real flow.
- Keyboard probe on the title screen: pressing **Tab** left focus on `<body>`.
  This is a confirmed defect, not a theoretical concern.

## 3. Batched edit request and acceptance tests

### Batch A — Input, screen entry and accessible reading

**Files:** `src/main.js`, `src/ui.js`, `index.html`, `src/styles.css`,
`scripts/audit.mjs`

**Changes**

1. Move Tab ownership behind the `playing` state check. In menus and pause,
   let the browser move focus. While playing, Tab keeps its objective meaning
   and prevents focus from leaving the game.
2. Add `Esc` back behaviour for settings and manual overlays, and make `Esc`
   dismiss the tutorial before it pauses the game.
3. Remove `aria-live` from the whole HUD. Keep live announcements on toasts,
   the crisis readout and other deliberately short-lived status surfaces.
4. Allow page zoom and add an inline SVG favicon.
5. Add `Shift` and `Tab` to the pocket-card control list, and document the
   tutorial `Esc` dismissal.
6. Expand the visible focus ring to all interactive controls.

**Acceptance:** Tab focuses an actionable menu button on title; Enter activates
Begin Case; Tab/Shift-Tab works on pause, settings and hub; HUD no longer floods
a live region; viewport is zoomable; no 404 favicon; audit checks the contracts.

### Batch B — Settings and save-boundary reliability

**Files:** `src/main.js`, `src/ui.js`, `index.html`, `src/styles.css`,
`scripts/audit.mjs`

**Changes**

1. Apply slider changes live without writing storage on every `input`; persist
   on `change`/commit.
2. Align sensitivity bounds between UI and sanitiser.
3. Import success refreshes the settings screen instead of jumping to the hub,
   preserving the state-machine context; reset the file input so the same file
   can be imported again.
4. Expose a real three-tier quality choice, or collapse the data to two tiers.
   Prefer exposing **LOW / MEDIUM / HIGH** with bloom only on HIGH and adaptive
   resolution on HIGH/MEDIUM.
5. Add an audit check that the settings write path is not called per input and
   that all quality tiers are renderable.

**Acceptance:** dragging a slider updates the view without touching storage
until release; sensitivity 0.2 survives reload; import from pause returns to
settings with the imported values visible; same-file import works twice.

### Batch C — Run continuity, data discipline and verifiable seeds

**Files:** `src/main.js`, `src/entities.js`, `src/content.js`,
`scripts/audit.mjs`

**Changes**

1. Keep a checkpoint at the completion of an organ until the next organ has
   actually loaded. A reload at the route screen must not erase the case. It is
   acceptable for the recovered save to restart the completed organ; losing the
   run is not acceptable. This rewind must be documented in the audit report.
2. Replace the spore Host literal with `HOST.sporeBurstCost`.
3. Move loot tuning to a `PICKUPS` block in `content.js` and import it into the
   runtime.
4. Seed shot spread and boss hazard/ring/summon/barrage choices from the run RNG.
   Keep FX-only randomness unseeded.
5. Add audit checks for the literal, the pickup block and the seeded boss paths.
6. Add a lightweight **runtime smoke probe** document/script so the next pass can
   replay the eight-organ, Tab, checkpoint and full-loop checks without relying
   on chat memory.

**Acceptance:** reload at an inter-organ screen offers Continue and does not lose
the case; no gameplay-affecting Host number is hard-coded outside content; same
seed produces the same boss attack decisions; audit catches regressions.

### Batch D — Accessibility presets

**Files:** `src/main.js`, `src/ui.js`, `src/styles.css`, `src/entities.js`,
`src/fx.js`, `scripts/audit.mjs`, `design/SMOKE-TEST.md`

**Changes**

1. Add a persisted **HIGH CONTRAST** preset: solid HUD glass, brighter labels and
   numbers, stronger meter tracks, no film grain or lens specks, stronger
   minimap contours and a white contour around infection nodes.
2. Add a persisted **REDUCE MOTION** preset: stills head bob, strafe roll,
   landing dip, sprint FOV widening, screen shake and decorative HUD/entry
   pulses. It does not alter movement speed, aim, damage, Host Integrity, timers
   or score.
3. Sanitise both booleans on import and seed the per-organ FX layer from the
   persisted preset, so it does not revert when a new organ loads.
4. Extend the audit and smoke procedure to cover both presets.

**Acceptance:** both toggles persist through reload; high contrast visibly
changes HUD and minimap; reduce motion removes camera motion while the simulation
still runs; the audit rejects presentation flags leaking into gameplay math.

### Batch E — Colour-vision mode

**Files:** `src/main.js`, `src/ui.js`, `src/styles.css`, `scripts/audit.mjs`,
`design/SMOKE-TEST.md`

**Changes**

1. Add a persisted **COLOR VISION** choice: STANDARD, DEUTERANOPIA,
   PROTANOPIA, TRITANOPIA.
2. Implement **LMS daltonization** in the linear-light grade shader, using the
   Viénot/Brettel/Mollon simulation matrices and the standard error-
   redistribution matrix. This moves the red/green infection signal into
   colour channels a dichromat can still separate instead of merely simulating
   the deficiency.
3. Switch HUD accent hues with the mode: blue/orange for deuteranopia and
   protanopia, red/green for tritanopia, so DOM status text stays separable even
   though the 3D canvas is handled by the shader.
4. Sanitise the mode on save import and extend the audit and smoke procedure.

**Acceptance:** all four modes compile and render; each mode changes the output
frame; HUD variables change with the mode; the mode survives reload; OFF returns
the untouched grade; no gameplay number changes.

### Deferred beyond this pass

- Colour-vision mode has been validated mathematically and by frame-buffer
  sampling, but not by a diagnosed colour-blind playtester. A human usability
  pass is still required.
- Gamepad has been verified with a synthetic standard-mapping pad, not physical
  hardware; rumble/haptics are not implemented.
- Cloud-save backend (explicitly out of the static slice).
- Automated headless browser suite; the current live checks are manual agent
  probes, not a CI gate.

Deferred items are not marked complete. They are scheduled work with a known
place in the pipeline.

## 4. Production rule for this pass

No accepted fix may change enemy damage, Host Integrity, score, the fixed 60 Hz
step or accessibility-as-difficulty. Presentation and input comfort may change;
the patient's math may not.

The conductor will only mark a batch complete after:

1. `npm run build` passes.
2. `npm run audit` passes with no new warnings.
3. The affected browser interaction is exercised.
4. The result is written back into this document with files, checks and any
   remaining limitation.

### Batch F — complete (controller play)

**Changed:** `src/content.js`, `src/main.js`, `src/entities.js`, `src/ui.js`,
`src/styles.css`, `scripts/audit.mjs`, `design/SMOKE-TEST.md`.

- Standard mapping: left stick moves with a radial deadzone and normalized
  diagonal, right stick looks in the fixed step, RT fires, LT braces, RB holds
  cautery, R3 sprints, START pauses, VIEW repeats the objective, A dashes, X
  reloads, B stabilizes, Y uses a medkit, LB throws a grenade and D-pad up spends
  Vital Focus. Tuning lives in `GAMEPAD` in `content.js`.
- The pad is a second input device. Keyboard and mouse state is never cleared by
  releasing the controller, and pad look uses the same sensitivity and invert
  settings as the mouse.
- Menus are pointer-free: D-pad steps controls, A activates, B backs out,
  left/right adjusts ranges and selects. Focus rings are explicit under
  `html[data-input="gamepad"]`.
- Live testing found and fixed two real controller defects. The same A press that
  established focus also activated the control, skipping a screen; a newly
  mounted screen also dropped focus entirely. Focus now starts on the screen’s
  forward action (`.cta` / `.menu-btn.primary`), is restored on screen change,
  and the focusing press does not activate.
- Synthetic standard-mapping probe, driven through the real `pollGamepad` and
  simulation step: title → case → loadout → injection via pad alone; left stick
  moved 3.13 m in the stick direction; right stick changed yaw by −0.86 rad and
  pitch by +0.43 rad; LT produced `aiming = true`; RT consumed 2 rounds over 14
  fixed steps; RB, R3 and the pad state reported held interact/sprint; START
  paused with focus on RESUME and A resumed to play.
- Remaining limitation: verified with a synthetic pad, not physical hardware.
  Rumble/haptics are not implemented.

### Batch G — complete (exact route-screen restoration)

**Changed:** `src/main.js`, `src/ui.js`, `scripts/audit.mjs`,
`design/SMOKE-TEST.md`.

- Organ completion now stores `stage: 'interorgan'` plus the cleared organ’s
  node/clean/time/host stats in the checkpoint. The title’s Continue label reads
  ROUTE CHOICE instead of IN PROGRESS for that checkpoint.
- Adaptation and route selections call `recordInterorganChoice()`, so the
  checkpoint is updated as the player chooses rather than only at descent.
- Continue validates the route-stop checkpoint (cursor must still point at the
  saved organ) and rebuilds the exact route screen via `restoreInterorgan()`.
  No organ is replayed, no injection overlay is shown, and both selections are
  restored.
- Descending clears the route-stop payload; the next organ’s checkpoint is
  written with `stage: 'organ'`, so the stale screen cannot be reopened later.
- Live probe: completed the lung, saved adaptation `overclock` and route
  `vagal`, reloaded, and Continue restored HOST 73, NODES 0/5, CLEAN 0,
  TIME 00:00 with both cards selected and ENTER enabled. Descending moved the
  cursor to 1, loaded marrow, and the checkpoint became organ-stage with no
  route payload.
- The audit gate now rejects a completion checkpoint without route payload,
  a Continue path that cannot rebuild the screen, and unvalidated route stops.

### Remaining limitations

- This is a scripted live-browser audit, not a complete 20–40 minute human
  playthrough. Pacing, fatigue and long-session memory growth still need that
  pass.
- Gamepad is implemented and verified with a synthetic standard-mapping pad,
  but not with physical hardware; rumble/haptics are absent. Cloud saves and a
  true CI browser suite remain deferred.
- The crisis and settings probes use the development debug handle. Production
  keeps the same behaviour but does not expose that handle.
- The local meta counters were touched by automated runs; the test checkpoint
  and synthetic imported counters were cleared afterwards.
